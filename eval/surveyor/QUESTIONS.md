# Question-led as-built survey — experimental treatment

Same report contract, source scope and quality criteria as SURVEY.md. This is a
prescribed research workflow, not a test of spontaneous native-tool adoption.
Do not write a baseline, persistent memory or skill, or infer design intent.

1. Inspect only enough launch/manifests to frame an initial agenda of 4–8
   concrete repository-behavior questions. Include entrypoints, state ownership,
   a primary request and background path, configuration, and consequential
   failure/alternative behavior. These are research questions, not user intent
   questions. Do not start by reading every source file.
2. Ask the questions to Jev through the explicitly offered tools. Begin with
   search_code for an unknown behavior location. For a known file, batch related
   questions in ask_file. Ask about supporting conditions, not just existence:
   what crosses the boundary, what identity/revision survives, and when an
   effect can occur. Exact identifiers/literals still belong in Grep.
   Both native tools send eligible synthetic source to TypeSafe and incur paid
   requests. Availability and this prescribed usage do not prove usefulness.
3. For each consequential answer maintain a small working evidence map in task
   context: question → source locations → observed/inferred/unknown claim →
   counterevidence or open follow-up. Distinguish syntactic references from
   runtime dispatch. A model score or matching quote does not verify semantics.
   This map is temporary task context; the offline explore.py ledger is a
   separate prototype, not an available model tool in this comparison.
4. Choose follow-up questions from the highest-impact unresolved claim, rather
   than a fixed number of paid rounds. Read exact returned ranges and missing
   neighboring context to verify evidence; do not reopen every shortlist file.
   Now read __METHOD_DIR__/TRACE.md. Seek an alternative state or counterexample:
   copied payload vs identifier, revisions/cache keys, pending/completed/failed
   work, identity reuse, acknowledgements and dynamic registration where relevant.
5. Stop at sufficient support and counterchecks or the shared task budget. On
   native failures, use Read/Grep and disclose the fallback; never equate missing
   evidence with absent behavior. Read __METHOD_DIR__/REPORT.md and return the
   same final report schema as the read-led survey, with calibrated unknowns.

This treatment changes tool-selection instructions as well as investigation
order. Comparisons must report that confound and actual native usage/costs.
The Claude dollar cutoff does not cap Jev expenditure. No automatic retries or
claim of combined savings when grep usage is unknown. Production onboarding is
unchanged, and independent semantic review remains necessary.
